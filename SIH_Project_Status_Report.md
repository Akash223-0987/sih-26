# SIH Project Status Report: Universal Log Pre-processing Framework (ULPF)

## 1. Problem Statement Requirements vs. Current Status

The solution requires a framework capable of ingesting, parsing, normalizing, and standardizing logs and events generated by diverse hardware/software systems, preserving original data, and enabling ML/SIEM integration.

### a) Preserve complete raw event data without information loss
- **Status:** **✅ Completed**
- **Details:** The ULPF architecture guarantees lossless preservation by storing the complete original log line verbatim in a `raw_message` field in ClickHouse, as documented in the Canonical Schema.

### b) Extract and parse source-specific attributes
- **Status:** **✅ Completed**
- **Details:** The Fluent Bit collection layer uses 7 format-specific parsers to ingest logs. Format-specific attributes not mapped to standard fields are preserved in the `extra_attributes` JSON string.

### c) Normalize fields into a common event taxonomy
- **Status:** **✅ Completed**
- **Details:** All formats are mapped to a flat Canonical Schema containing standard fields such as `event_id`, `timestamp`, `log_source`, `severity`, `src_ip`, `dest_ip`, `dest_port`, `user_name`, `action`, and `protocol`.

### d) Maintain traceability between normalized and original events
- **Status:** **✅ Completed**
- **Details:** Traceability is maintained via a unique UUID `event_id` assigned to each normalized event, paired directly with the `raw_message` field.

### e) Plug-and-play onboarding of new log sources
- **Status:** **✅ Completed**
- **Details:** The solution supports 7 industry log formats out of the box (JSON, Syslog RFC5424/3164, CEF, LEEF, Apache/Nginx, Windows Event CSV) using dedicated Fluent Bit `[INPUT]` blocks and auto-detects formats. Extending it requires only adding a new regex/json parser in `parsers.conf`.

### f) Unified visibility across enterprise environments
- **Status:** **✅ Completed**
- **Details:** Achieved through the `logs_normalized` table in ClickHouse for analytics, and a Threat Correlation Graph in Neo4j that models IP-to-IP and IP-to-User relationships from every normalized event.

### g) Efficient SIEM and Data Lake integration
- **Status:** **✅ Completed**
- **Details:** The pipeline utilizes a Kafka broker (`enterprise-logs` topic) as a central nervous system. Downstream, it writes to a ClickHouse data lake and Neo4j, making it integration-ready for SIEM platforms.

### h) AI/ML-ready security and operational analytics
- **Status:** **✅ Completed**
- **Details:** An ML Inference FastAPI Service (`ml_service.py`) and Threat Detection Service (`threat_detector.py`) are fully implemented and verified. It employs a trained `LGBMClassifier` (`models/threat_model.joblib`) for predicting threats like Brute Force, Lateral Movement, Exfiltration, and Port Scans with sub-5ms latency.

### i) Reduced parser development effort
- **Status:** **✅ Completed**
- **Details:** Achieved via the lightweight `PyTrace` Python SDK which auto-instruments applications to emit structured logs natively, removing the need for parsers at the source. It also features heuristic format auto-detection for legacy logs without metadata.

### j) The solution shall be deployable in an air-gapped network
- **Status:** **✅ Completed**
- **Details:** The pipeline is designed to be fully containerized without requiring external internet connectivity after the initial image pull.

### k) Solution may be packaged in a container for making it platform independent
- **Status:** **✅ Completed**
- **Details:** A full stack `docker-compose.yml` (Kafka, Fluent Bit, ClickHouse, Neo4j, ML Services) is provided in the `infra/` directory.
